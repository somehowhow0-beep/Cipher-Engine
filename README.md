# Cipher-Engine

A TypeScript project exploring seed-driven cryptographic building blocks. It currently implements key derivation, deterministic pseudorandom streams, and generated byte-substitution and permutation tables. **It does not currently implement an end-to-end encryption/decryption API.** In particular, although the package description mentions a hybrid design with AES-256-GCM, there is no AES-GCM encryption layer or message envelope in the source yet.

> **Security status: experimental; not for protecting real data.** The components in this repository are not a complete, reviewed cryptographic system. The generated inner transformations should not be treated as encryption or as an added security guarantee.

## What is implemented

- **Seed and key derivation (`src/kdf.ts`)**: normalizes string seeds with Unicode NFKC, derives a 32-byte master key with scrypt, then uses HKDF-SHA-256 to derive separate `engine`, `aead`, and `decoy` keys. The default scrypt parameters are `N = 2^17`, `r = 8`, `p = 1` (about 128 MiB); input parameters are bounded by a policy to limit excessive resource use.
- **Deterministic pseudorandom streams (`src/prng.ts`)**: derives a stream key from a key and label with HKDF-SHA-256, then generates bytes with AES-256-CTR. The same key and label intentionally produce the same stream. Child streams can be forked by label.
- **Generated transformations (`src/generators/`)**: `sbox.ts` generates byte substitution tables and measures nonlinearity and differential uniformity; `permutation.ts` generates reversible byte-position permutations.
- **Tests (`test/`)**: exercise derivation vectors, input validation, deterministic output, transformation inverses, and selected statistical/quality properties. Passing these tests does not establish that the overall design is secure.

## Security considerations

- **There is no complete encryption method to assess or use yet.** The repository has no message format, encryption/decryption functions, nonce handling, authentication-tag handling, or end-to-end tests for encrypted data.
- AES-256-GCM is a widely used authenticated-encryption primitive, but its mention in the package description is not an implementation. A future implementation must correctly generate and store a fresh nonce for every encryption under a given key, authenticate relevant metadata, and reject tampered ciphertext before returning plaintext. GCM nonce reuse can catastrophically undermine security.
- S-boxes and permutations alone do not provide secure encryption. Custom, seed-generated inner transformations do not replace a standard, reviewed authenticated-encryption construction, and layering them does not automatically make a system stronger.
- A passphrase's security depends on its entropy. Scrypt slows guessing but cannot make a weak or reused passphrase strong. The KDF's best-effort buffer wiping also cannot guarantee erasure from JavaScript process memory.
- The cryptographic code has not been independently audited. Do not rely on it for production, sensitive, or irreplaceable data.

## Requirements

- Node.js 18 or later
- npm

The project has no runtime npm dependencies; TypeScript and Node.js type definitions are development dependencies.

## Build and test

```bash
npm install
npm run build
npm test
```

`npm test` builds the TypeScript and runs the compiled tests with Node's built-in test runner. To remove generated build output:

```bash
npm run clean
```

## Source layout

```text
src/
  kdf.ts                  Seed-to-key derivation and key lifecycle helpers
  prng.ts                 Labeled deterministic pseudorandom byte streams
  generators/
    sbox.ts               Generated byte substitution tables and quality metrics
    permutation.ts        Reversible byte-position permutations
test/                     Tests for the implemented components
```

## Project status

This is a private, unlicensed (`UNLICENSED` in `package.json`) early-stage project. It is not currently published as a package and has no documented command-line tool or server. Review the code and security status before using or extending it.
